# Decisions

The distilled rulings from resolved discussions. The argument may compact away; the ruling survives. Never re-litigate an entry without acknowledging it.

- Decided: Clyde's identity line is "Claude Code treats the transcript as a log; Clyde treats your conversation as a workspace" — lead the README with it, because the user confirmed it captures the whole idea (2026-08-18)
- Decided: threading is a presentation layer over one linear conversation, never context forking — because it keeps the model coherent and makes the POC tractable (2026-08-18)
- Decided: backend is the TypeScript Agent SDK, UI is a local web app launched Jupyter-style (`clyde .`), one process per project — because it maximizes leverage from the Claude Code harness and matches how the user works (2026-08-18)
- Decided: all persistent state lives as plain files in `.clyde/`, committed to the repo — because the model reads/writes them natively, git versions them, and nothing dies with a process (2026-08-18)
- Decided: steering is queue-at-turn-boundary with a per-item urgent interrupt — because auto mode must not be blocked, but the user keeps an emergency brake (2026-08-18)
- Decided: context v1 is visualize + re-inject only; true eviction is a v2 spike — because transcript-rewrite forking is the riskiest unknown and shouldn't gate the POC (2026-08-18)
- Decided: first mission is Clyde building Clyde, with Playwright screenshot QA pushed to a gallery panel — because the dogfood loop is the fastest way to hit every UX pain (2026-08-18)
- Decided: reviews are a first-class noun — batch feedback lives in .clyde/reviews/*.md checklists, triaged item-by-item (accept-as-task / fix+sha / push-back), rendered as a burn-down panel — because testing waves are how the user actually steers QA (2026-08-18)
- Decided: commit expansion stays v1-simple — an expandable card fed by GET /api/commit (git show --stat --patch); GitHub diff deep-links wait for push/remote awareness (2026-08-18)
- Decided: non-urgent messages now steer mid-turn by default (CLYDE_STEERING=0 reverts) — supersedes the queue-at-turn-boundary ruling above, because questions stuck behind long working turns broke conversational flow; the urgent interrupt is unchanged (2026-08-18)
- Decided: new nouns face a high bar — not a ban — and the bar is the lifecycle test: an object earns persistence only when it has a lifecycle no existing noun can carry; otherwise build a lens over existing nouns. Agents pass (running/completed + live activity); Reviews and Q&A fail — reviews fold into Tasks (source provenance, declined-with-reasons state, intake-batch grouping; Reviews tab becomes a lens) and answered questions distill into Decisions and/or Tasks (2026-08-18)
- Decided: the composer collapses to Send / Stop / Stop & send — steering made "Queue" stale copy and three buttons confused; Enter sends, Shift+Enter newlines (Slack semantics), only Stop & send jumps the FIFO line (2026-08-18)
- Decided: message delivery is strictly FIFO across restarts and steering — queued leftovers flush before any newer delivery, because the user observed out-of-order arrivals and order is trust (2026-08-18)
- Decided: attachments are files-as-database — uploads land in .clyde/uploads/ (gitignored), messages carry project-relative paths, the agent Reads them natively; no base64 blocks in the event log (2026-08-18)
- Decided: turns cut short by a server restart auto-resume (option 2: visible synthetic message, once per boot, queue takes precedence, 30-min freshness, crash-loop guard) because Clyde-builds-Clyde restarts the backend constantly and manual nudging defeats auto mode (2026-08-18)
- Decided: sidebar replies post via the reply_in_thread tool, not output markers — supersedes the [[sidebar:<id>]] marker ruling, because the transcript showed 0/22 marker compliance under work-load while tool-call discipline holds; agent-to-UI structured output should always prefer a tool call over a formatting convention (2026-08-18)
- Decided: the [Auto-resume] synthetic message delivers silently — recorded in events.jsonl but not rendered in the conversation (amends the "visible" clause of the auto-resume ruling) because once trusted it is plumbing, and the document is for prose (2026-08-18)
- Decided: `.clyde/sessions/` is gitignored — narrows the "all .clyde/ state is committed" ruling to human-curated state (tasks, decisions, reviews, panels), because the event log is an append-only machine artifact that keeps the tree perpetually dirty and bloats diffs, and resume reads it from disk regardless of git (2026-08-18)
- Decided: sidebar answers live only in the thread — no main-flow recap of a reply_in_thread response, because the duplication doubled every answer into clutter; main prose appears only for separate main-line work the sidebar spawned (2026-08-18)
- Decided: the noun is Threads, not Comments — a comment is just one way to start a thread (select-text seeds the quote; threads can also start from any message, including the user's own), and multiple threads per message off different highlighted spans must keep working because the user leans on it (2026-08-18)
- Decided: Resolve on a thread is presentation plus a distillation nudge — it collapses the card and prompts the agent to capture any settled ruling into DECISIONS.md, and it never touches Tasks/Decisions/work the thread spawned (2026-08-18)
- Decided: the agent session loads only MCP servers Clyde names explicitly (`strictMcpConfig: true`) — account-level claude.ai connectors otherwise ride in on the user's login and inject OAuth nags the user doesn't care about (2026-08-18)
- Decided: resolving a thread is silent — no agent notification, no closing reply; amends the distillation-nudge clause above, because rulings get recorded when they settle mid-thread, so the nudge only ever bought a "closing out" turn of noise for real tokens (2026-08-18)
- Decided: Review is an intake ceremony, not a storage noun — refines the lifecycle-test ruling with the missing design: dump feedback (button-initiated "Start review" mode OR agent auto-detects an unprompted feedback dump and offers the same ceremony) → raw dump saved verbatim to .clyde/reviews/<date>-<slug>.md as provenance → agent distills to numbered items and echoes them back → clarifying questions via the real AskUserQuestion → confirmed items become Tasks with source provenance, batch id, and declined-with-reasons state → Reviews tab renders a burn-down lens over task batches. Because the satisfaction the user wants (blab → crisp checklist) lives in the ceremony, and prose checkboxes are the medium that produced R6's false "verified" — structured task state cannot drift from reality (2026-08-18)
- Decided: the right workbench is the attention surface, not a panel registry — it carries structured interaction that needs the user's eyes now (AskUserQuestion cycles, review-intake ceremonies, model-pushed "see this now" exhibits), while durable reference state demotes to left-rail tabs (Goal/Scope doc, QA artifact galleries) — because the right rail earns its persistent screen space by carrying interaction, not wallpaper; the question experience is the first test of this workflow (2026-08-18)
- Decided: worktree isolation is the standard pattern for parallel implementation subagents in Clyde-builds-Clyde — in-tree agents collide on hotspot files and any packages/server/src edit restarts the live server killing all running agents, so agents build in worktrees and the coordinator owns every merge; the full doctrine (explicit bases, merge order, conflict protocol, QA gates) gets codified as #22 and the agent+worktree state surfaced in UI as #23, because orchestration mechanics re-derived per session are orchestration mechanics waiting to fail (2026-08-18)
- Decided: the review ceremony's confirm step is a question-card confirm in v1 — the distilled checklist echoes in conversation and item selection happens via one multiSelect AskUserQuestion card in the workbench, chosen (via the question tool's first production use) over a dedicated intake card, which must earn its build after the flow is felt, and over prose-only creation (2026-08-18)
- Decided: redesign chrome is stretch-real — build every top-bar/shell control that can be genuinely functional today (branch + working-tree state, agent status, session cost, New session, Pause→interrupt, effort display) and leave designed slots for the rest (project/branch pickers, ⌘K jump, tests tile); never ship dead controls, because placeholder chrome erodes trust in what's real (2026-08-18)
- Decided: the Tasks-panel dispatch preview is declined until a real dispatch-from-task flow exists — applying the stretch-real ruling: a UI-computed "what the brief would look like" is a guess at what the coordinator actually sends, and honest chrome beats plausible chrome; SCOPE keeps preview-and-edit as direction attached to that future flow (2026-08-18)
- Decided: the north star sharpens to "make it safe and intelligible to build software without needing to read the code," on two pillars — craft (care more about the product without inspecting the implementation) and rigor (the burden of proof gets higher, not lower) — with the per-feature test "does this increase justified confidence without requiring implementation inspection?" Because it explains *why* the conversation is the workspace, and it generates decisions the way the lifecycle test does (2026-08-18)
- Decided: the README goes thesis-first at our density — the provocative question and the two pillars lead, compressed hard from the reviewer's draft (its one-sentence-per-line manifesto cadence rejected as too marketing-y); concrete sections, screenshots, and tables stay; unbuilt items marked as direction.
