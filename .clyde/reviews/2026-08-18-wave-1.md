# Review — wave 1 (2026-08-18, first hands-on session)

Source: the user's first real test of the walking skeleton, with screenshots.
Protocol: triage every item — accept into a task (note it), fix directly (check off
with the commit sha), or push back with reasons (never silently drop). The user
verifies checked items.

- [ ] R1 — Tasks panel: items must be clickable to expand — full detail, edit
  subject/status from the UI, and (per SCOPE.md) show what the dispatch prompt to a
  subagent would look like, editable.
- [ ] R2 — Git timeline: commits must be clickable to expand — full commit message,
  per-file diffstat, and the jump-to-conversation link made obvious.
- [ ] R3 — Right rail: must be expandable/resizable (the goal doc is cramped at a
  fixed 290px); ideally the goal document (SCOPE.md) is editable in place — edit →
  save to file → agent notified it changed.
- [ ] R4 — New first-class noun, the Review: an affordance for batch feedback from a
  testing wave. Items with optional screenshots/quotes, each tracked
  open → accepted(task) → addressed(commit) → verified, or declined(reasons).
  Stored as files in .clyde/reviews/ (this file is the v0), rendered as a panel with
  burn-down, items thread-anchorable. Add to SCOPE.md and the standing orders
  (triage every item, check off with commit links).
